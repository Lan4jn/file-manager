# v1.8 Workbench Design

## Overview

v1.8 在现有完整版界面中新增一个聚合型“工作台”首页，用于承接登录后的首屏体验、目录快捷访问和分享提醒，并补齐文件管理中的重命名能力。该版本同时覆盖四类需求：工作台入口与默认首页偏好、目录历史与收藏目录、分享实时横幅提醒、文件与目录重命名及上传前改名。设计目标是在尽量复用现有用户配置、消息推送、文件操作和上传流程的基础上完成增量扩展，避免引入新的重型模块。

## Goals

- 新增左侧一级菜单“工作台”，作为登录后的可选默认首页
- 在工作台中并列展示“最近访问目录”和“收藏目录”
- 为分享发起人与接收人都提供实时横幅提醒
- 支持已存在文件/目录重命名
- 支持上传队列中的单文件改名和批量规则改名
- 保持现有权限、消息中心、文件浏览与上传流程可用

## Non-Goals

- 不新增“收藏文件”能力，本版只收藏目录
- 不新增独立的目录历史管理页
- 不为工作台建立独立权限体系
- 不引入复杂的模板化批量改名规则
- 不修改轻量版页面行为

## Scope Summary

### Included

- 左侧新增 `workbench` 菜单
- 登录后根据用户偏好决定首屏进入工作台还是现有默认页
- 工作台页面内提供“下次登录默认显示工作台”复选框
- 工作台首页显示欢迎区、最近访问目录、收藏目录、提醒摘要
- 当前用户全局范围的目录历史记录与收藏目录管理
- 分享成功时对发起人显示即时横幅
- 收到别人分享时对接收人显示即时横幅
- 单文件/目录重命名
- 上传前逐项改名与批量规则改名

### Excluded

- 收藏文件与最近文件
- 目录历史手动编辑、排序与高级筛选
- 横幅提醒持久化为完整通知中心新模块
- 批量改名模板变量、序号插入、正则改名

## User Experience

### Left Navigation

左侧导航新增一级入口“工作台”，放在现有核心入口附近。用户点击后进入聚合首页，不替代现有的“文件管理”“我的分享”等页面。

### Login Landing

登录成功后，前端在完成用户信息与运行时配置加载后，读取工作台偏好：

- 若 `defaultWorkbench = true`，则将 `currentMenu` 设为 `workbench`
- 否则继续使用现有默认首页逻辑

该决策在登录回调中直接生效，避免先进入其他页面再跳转造成闪烁。

### Workbench Layout

工作台页面包含四个区域：

1. 顶部欢迎区
   - 展示当前用户名、快捷入口
   - 包含“下次登录默认显示工作台”复选框

2. 最近访问目录卡片
   - 展示当前用户全局最近访问目录
   - 按最近访问时间倒序
   - 支持点击进入对应桶和目录

3. 收藏目录卡片
   - 与最近访问目录并列展示
   - 支持点击进入目录
   - 支持取消收藏

4. 提醒摘要区
   - 展示近期分享提醒摘要
   - 横幅本身为即时浮层，摘要区用于避免用户错过最近几条提醒

### Real-Time Share Banner

分享提醒分成两条链路：

- 发起人链路
  - 分享成功后前端本地立即弹横幅
  - 内容包含分享对象、分享名称、是否生成链接/提取码等信息

- 接收人链路
  - 复用现有消息推送或消息同步机制
  - 收到新的分享消息时，额外触发顶部横幅
  - 横幅点击后可跳转到收件箱或打开相关分享

### Rename Experience

重命名使用统一弹窗，支持文件与目录：

- 打开后预填当前名称
- 前端先做名称合法性校验
- 若发生同目录同名冲突，前端展示三选一：
  - 覆盖
  - 自动重命名
  - 取消

取消由前端直接结束流程，不向后端发起二次请求。

### Upload Rename Experience

上传队列中每个文件项展示：

- 原始文件名
- 可编辑目标文件名
- 所在目录信息

同时提供批量规则改名入口。第一版规则仅支持：

- 添加统一前缀
- 添加统一后缀
- 查找替换

用户确认后，以修改后的目标文件名参与后续上传流程。

## Architecture

### Frontend

- 在 `index.html` / `app.js` 中新增 `workbench` 页面分支与状态管理
- 工作台首页通过新的聚合接口获取偏好、最近目录、收藏目录和提醒摘要
- 登录后首屏决策整合到现有登录成功流程
- 分享成功时由分享创建逻辑直接触发发起人横幅
- 接收人横幅复用现有消息接收逻辑，在消息到达时追加横幅事件
- 上传对话框扩展目标文件名编辑能力，并将最终文件名传递给现有上传链路

### Backend

- 新增工作台聚合服务，封装偏好读取、历史目录、收藏目录和提醒摘要查询
- 新增或扩展用户偏好存储，用于保存默认进入工作台的选择
- 在目录加载成功后记录目录历史
- 新增收藏目录的增删查接口
- 新增重命名接口，支持冲突策略
- 扩展上传准备流程，接受上传前改名后的目标文件名

## Data Model

### User Workbench Preference

建议新增轻量用户偏好表或挂接到现有用户配置结构：

- `userId`
- `defaultWorkbench`
- `updatedAt`

约束：

- 每个用户一条记录
- 未配置时默认 `false`

### Directory History

- `id`
- `userId`
- `bucketName`
- `directoryPath`
- `directoryName`
- `lastAccessTime`

约束：

- `userId + bucketName + directoryPath` 唯一
- 重复访问仅更新时间
- 保留最近固定条数，例如 50 条

### Favorite Directory

- `id`
- `userId`
- `bucketName`
- `directoryPath`
- `directoryName`
- `createTime`

约束：

- `userId + bucketName + directoryPath` 唯一

### Share Banner Event

优先复用现有消息/推送体系，不单独新增重表。为横幅提醒定义统一事件载荷：

- `eventType`
- `title`
- `content`
- `shareCode`
- `senderUsername`
- `targetUsername`
- `createTime`

事件类型至少包含：

- `SHARE_SENT`
- `SHARE_RECEIVED`

## API Design

### Workbench

- `GET /api/workbench/overview`
  - 返回欢迎区所需信息、默认首页偏好、最近访问目录、收藏目录、提醒摘要

- `PUT /api/workbench/preference`
  - 更新 `defaultWorkbench`

### Favorite Directory

- `GET /api/workbench/favorites`
- `POST /api/workbench/favorites`
- `DELETE /api/workbench/favorites`

### Directory History

目录历史不单独暴露“进入目录即上报”的新前端接口。优先在现有目录加载成功后，由后端在文件列表服务内部自动记录目录访问历史，减少前端额外调用点。

### Rename

- `POST /api/file/rename`

请求字段建议包含：

- `bucket`
- `sourcePath`
- `targetName`
- `directory`
- `conflictPolicy`

其中 `conflictPolicy` 支持：

- `OVERWRITE`
- `RENAME`

### Upload Preparation

不新增独立上传改名接口。扩展现有上传准备/直传会话创建参数，支持：

- `originalFileName`
- `targetFileName`

最终仍由后端负责对象路径生成、合法性校验和冲突控制。

## Interaction Rules

### Default Workbench Preference

- 开关只放在工作台页面内
- 修改后立即保存
- 保存失败时回滚勾选状态并提示错误

### Directory History Recording

- 仅在目录加载成功后记录
- 无权限目录、加载失败目录、不存在目录不写入历史
- 写入历史失败不阻断页面浏览

### Favorite Directory Handling

- 收藏成功后立即刷新工作台列表
- 若目录失效或无权限，则在工作台显示“目录不可用”
- 用户可直接清理失效收藏

### Rename Conflict Handling

当后端返回目标同名冲突时：

1. 前端弹出冲突处理选择框
2. 用户选择：
   - 覆盖：以 `OVERWRITE` 二次提交
   - 自动重命名：以 `RENAME` 二次提交
   - 取消：直接结束流程

### Upload Rename Rules

- 单文件可直接编辑目标文件名
- 多文件支持批量规则处理
- 规则执行后，用户仍可逐项微调
- 空名称、非法名称、仅扩展名等异常输入必须在前端拦截

## Error Handling

- 工作台偏好保存失败：回滚 UI 状态，提示“保存失败”
- 工作台聚合数据部分失败：页面可展示降级空状态，不阻断其他模块
- 目录历史写入失败：仅日志记录，不中断目录浏览
- 收藏目录新增/取消失败：提示错误并保持当前列表
- 分享接收横幅推送失败：不影响消息中心主流程
- 重命名失败：根据错误类型提示非法名称、权限不足、同名冲突或目录不可用
- 上传前改名校验失败：阻止进入实际上传

## Security and Permissions

- 工作台数据仅返回当前登录用户的数据
- 收藏目录和目录历史的查询与写入都必须绑定当前用户
- 重命名必须复用现有文件操作权限校验
- 上传前改名不能绕过现有上传权限、路径合法性与冲突校验
- 接收人横幅仅对当前登录用户自身的分享消息生效

## Testing Strategy

### Backend Tests

- 工作台聚合接口返回当前用户数据
- 默认首页偏好更新与读取
- 目录历史去重、更新和裁剪
- 收藏目录唯一性与删除
- 重命名成功、冲突、覆盖、自动重命名、权限不足
- 上传准备阶段接收目标文件名并保持正确对象路径

### Frontend Tests

- 登录后首屏根据偏好切换到工作台
- 工作台开关保存失败时回滚
- 最近访问目录和收藏目录卡片渲染与跳转
- 分享成功发起人横幅显示
- 接收人消息到达时触发横幅
- 重命名弹窗冲突分支
- 上传队列逐项改名和批量规则改名

### Manual Verification

- 登录后切换默认首页开关，退出重登验证
- 浏览多个桶和目录，检查最近访问目录排序与数量裁剪
- 收藏目录、取消收藏、访问失效目录
- 创建链接分享与站内分享，分别检查发起人横幅
- 用第二个账号在线接收分享，检查接收人横幅
- 重命名文件/目录并验证冲突三选一
- 上传前修改文件名并确认最终上传名称正确

## Rollout Notes

- 先保证工作台和重命名主流程可用，再逐步补充样式与提示文案
- 数据表新增应保持向后兼容，未配置用户偏好默认关闭工作台首屏
- 若消息推送链路不稳定，接收人横幅可先退化为依赖现有消息同步轮询
