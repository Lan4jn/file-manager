# v1.7 版本更新内容

## 消息与分享

- 新增站内分享收件箱，支持分享创建时指定系统用户作为接收方。
- 收件箱支持未读展示、标记已读、删除消息等操作。
- 分享列表新增“发给我的”视图，便于统一处理站内分享。
- 分享创建界面支持在链接分享和指定用户分享之间切换。

## 上传能力

- 新增上传会话接口，支持后端代理上传和 MinIO 预签名 PUT 直传。
- 直传上传完成后增加业务确认接口，补齐对象元信息并保持现有文件列表逻辑。
- 修复直传确认失败时的错误回退，避免对象已写入后再次重复上传。
- 上传失败提示细分为权限不足、文件过大、类型不允许、对象存储异常、确认失败、网络错误等分类。
- 上传完成提示改为右上角成功通知，支持撤销上传，采用浅绿色提示条样式并在 30 秒后自动关闭。
- 重构上传弹窗交互，支持拖入或点选后立即进入上传任务。
- 新增上传窗口触发模式和文件展示区拖拽触发模式的独立配置。
- 新增上传机制顺序配置，可控制直传与应用代理上传的优先级。
- 恢复旧版手动上传模式，支持先加入待上传列表再统一提交。

## 下载能力

- 下载链路统一收敛到 `transfer` 模块，区分应用下载、Jar 流式代理下载和 MinIO 直连下载。
- 新增 `DIRECT` 直连下载模式，可返回 MinIO 预签名 GET URL，由浏览器直接下载对象。
- 新增下载机制顺序配置，可控制直连、代理、应用下载的优先级。
- 批量下载与目录下载改为归档任务模式，前端通过轮询任务状态再触发下载。
- 分享归档任务支持在服务重启后基于持久化上下文恢复执行。
- 大文件下载优先尝试浏览器“边读边写磁盘”，失败后退到浏览器原生下载，最后回落到前端内存分块拼装。
- 大文件分块下载增加完整性校验，降低文件尾部损坏风险。
- 修复 `DIRECT` 下载回退与大文件浏览器接管状态显示，避免应用下载链路误报成功。
- 修复前台批量下载仍按硬编码 `2GB` 限制的问题，改为遵循系统配置的批量下载大小限制。

## 文件管理与界面

- 修复目录修改时间缺失时错误显示为当前时间的问题，改为按真实时间展示，缺失时显示为空。
- 兼容旧版 MinIO `lastModified` 字段缺失场景，避免文件列表因空时间直接抛异常。
- 调整文件列表分页，默认每页 `25` 条，支持 `25 / 50 / 100 / 200` 切换。
- 修复上传完成通知曾错误显示渲染函数源码的问题。
- 优化文件展示区拖拽高亮效果，修复拖拽时区域反复闪动的问题。
